# Project II 資料表規格

本文件說明需要在 Google Sheet 建立的所有表格。每張表對應一個分頁（Sheet），
匯出成 **JSON 陣列** 後存為 `Assets/ProjectII/Resources/GameData/{表名}.txt`。
目前專案內已放置一份可直接遊玩的虛構範例資料，欄位格式請以本文件為準。

> 匯出格式範例（每列一個物件，欄位名稱需與下方完全一致、區分大小寫）：
> ```json
> [
>   { "ID": 1, "Key": "Morning", "DisplayName": "早晨", "NextID": 2, "IsNewDay": 1, "AllowAction": 1, "Note": "" }
> ]
> ```

---

## 共通語法

### 條件式（Condition / VisibleCondition / EnableCondition 欄位）

- 以 `$標籤` 引用 GameValueData 表定義的數值，例如 `$Supplies >= 200`。
- 比較運算子：`>=` `<=` `==` `!=` `>` `<`
- 邏輯組合：`&&`（且）與 `||`（或），`&&` 優先；不支援括號。
- 兩側可寫四則運算與 `Random(min,max)`，例如 `$Supplies+$TradeCount*10 > 100`。
- **留空白 = 恆成立。**
- 系統保留標籤：`$Day`（天數）、`$CurrentPhase`（時段ID）、`$CurrentLocation`（地點ID）、
  `$EventDone_{事件ID}`（一次性事件是否完成）、`$LocationUnlocked_{地點ID}`（地點是否解鎖）。

### 效果指令串（Commands 欄位）

- 多個指令以 `;` 分隔，例如：`AddValue(Satiety,30);AdvanceTime()`。
- **指令內不可有空格以外的全形空白；系統會自動移除半形空格。**
- 數值參數可使用 `$標籤` 與四則運算，例如 `AddValue(Supplies,$TradeCount*100)`。

| 指令 | 說明 |
|---|---|
| `AddValue(標籤,公式)` | 數值加上公式結果（可為負），自動套用上下限 |
| `SetValue(標籤,公式)` | 數值設為公式結果 |
| `AdvanceTime()` | 推進到下一個時間階段（依 TimePhaseData.NextID，必要時換日） |
| `SetPhase(階段Key)` | 直接跳到指定階段（不換日），例如 `SetPhase(Evening)` |
| `MoveToLocation(地點ID)` | 移動到指定地點（會觸發 EnterLocation 事件） |
| `UnlockLocation(地點ID)` | 解鎖地點（= `SetValue(LocationUnlocked_{ID},1)`） |
| `StartDialogue(對話ID)` | 播放一段劇情對話並等待結束 |
| `ShowHint(文字ID)` | 顯示提示視窗（文字取自 GameTextData），等待玩家確認 |
| `Monologue(群組名)` | 從 GameTextData 依群組+條件加權隨機抽一句自言自語顯示於 HUD |
| `PlayPerformance(演出ID)` | 播放 UGUI 演出（見下方「演出」章節） |
| `OpenLocationMenu()` | 開啟移動選單讓玩家選地點（可取消） |
| `ReturnToTitle()` | 結束流程返回主標題（結局用） |
| `Wait(秒數)` | 暫停指令串指定秒數（演出節奏用） |

新增指令：實作 `EffectCommandBase` → 在 `EffectCommandRegistrar` 註冊一行即可。

### 觸發時機（GameEventTriggerData 的 Timing 欄位）

| 時機字串 | 觸發點 |
|---|---|
| `GameStart` | 開新遊戲後、進入第一個時間階段前 |
| `PhaseStart:{階段Key}` | 進入時間階段時，例如 `PhaseStart:Morning` |
| `AfterAction:{行動ID}` | 玩家行動的指令執行完畢後，例如 `AfterAction:106` |
| `EnterLocation:{地點ID}` | 移動到地點後，例如 `EnterLocation:4` |

**萬用時機 `Any`（保留字）**：冒號後寫 `Any` 可命中同類別的所有時機，
例如 `PhaseStart:Any`（每個時段開始）、`AfterAction:Any`（每個行動之後）。
與精確時機的事件混在同一份優先度佇列中執行。目前用於飽腹/精神歸零的
Game Over 判定（事件 190~193，優先度 1000/990 確保先於其他事件檢查）。
階段 Key 與行動 ID 因此不可命名為 `Any`。

## 1. TimePhaseData（時間階段表）

| 欄位 | 型別 | 說明 |
|---|---|---|
| ID | int | 唯一識別碼 |
| Key | string | 程式識別字（英文），`PhaseStart:{Key}`、`SetPhase(Key)` 引用 |
| DisplayName | string | HUD 顯示名稱 |
| NextID | int | 推進時間後進入的階段 ID |
| IsNewDay | int | 1=進入此階段時天數+1 |
| AllowAction | int | 1=開放玩家選擇行動；0=事件結束後自動推進 |
| Note | string | 備註（程式不讀） |

目前設定：早晨(1)→中午(2)→下午(3)→晚上(4)→早晨(換日)，每日四時段。
晚上開始時依序觸發丈夫返家與強制晚餐事件，之後開放夜間行動（求歡/就寢）。

> 時段自然消耗（每時段扣飽腹/精神）定義在 GameValueData 的 `PhaseDecay` 欄位，
> 只在時間「自然推進」（AdvanceTime）時扣除；`SetPhase()` 劇情跳轉不扣
> （交易返家後精神飽腹回滿即是利用這點）。

## 2. GameValueData（數值定義表）

| 欄位 | 型別 | 說明 |
|---|---|---|
| ID | int | 唯一識別碼 |
| Tag | string | 數值標籤（英文），條件式以 `$Tag` 引用 |
| DisplayName | string | HUD 顯示名稱 |
| InitialValue | int | 開新遊戲初始值 |
| MinValue / MaxValue | int | 上下限（AddValue/SetValue 自動鉗制） |
| ShowInHUD | int | 1=顯示於 HUD 狀態列 |
| PhaseDecay | int | 每次自然推進時段時扣除的量（飽腹=10、精神=9）；0=不消耗 |
| Note | string | 備註 |

新增旗標/數值直接加列即可，**程式不需要改動**。

目前玩法數值模型（皆可直接在表上調整）：
- 起始：物資 80、飽腹 100、精神 100；飽腹/精神歸零觸發 Game Over（事件 190~193）。
- 每時段自然消耗：飽腹 −10、精神 −9（每日四時段共 −40／−36）。
- 丈夫出門（早晨）：物資 −25；返家（晚上）：物資 +Random(40,100)，平均 +70。
- 強制晚餐（晚上）：物資 −40，飽腹 +20、精神 +18。
- 日間行動：料理（物資−15／飽腹+20／精神+18）、生食（−5／+6／−5）、
  清潔環境（精神+12）、休息（無增減）。
- 性交易：物資 +165，飽腹與精神回滿 100。

## 3. LocationData（地點表）

| 欄位 | 型別 | 說明 |
|---|---|---|
| ID | int | 唯一識別碼 |
| Name / Description | string | 名稱與說明 |
| VisibleCondition | string | 出現在移動選單的條件 |
| ShowInMenu | int | 1=顯示於移動選單（家中=0，回家請走「返回家中」行動以推進時間） |
| SortOrder | int | 選單排序 |
| Note | string | 備註 |

## 4. PlayerActionData（玩家行動表）

| 欄位 | 型別 | 說明 |
|---|---|---|
| ID | int | 唯一識別碼（AfterAction 事件以此引用） |
| Name / Description | string | 按鈕名稱與說明 |
| Locations | string | 可出現的地點 ID，逗號分隔（如 `"2,3,4"`；空白=所有地點） |
| VisibleCondition | string | 顯示條件（常用 `$CurrentPhase` 限制時段） |
| EnableCondition | string | 可點擊條件（不符合時按鈕反灰） |
| Commands | string | 效果指令串 |
| SortOrder | int | 選單排序 |
| Note | string | 備註 |

慣例：純機制行動（打掃/進食/休息）把效果直接寫在 Commands；
劇情行動（求歡/交易）Commands 留空，由 `AfterAction:{ID}` 事件依條件決定結果。

## 5. GameEventTriggerData（事件觸發表）— 劇情流程的核心

| 欄位 | 型別 | 說明 |
|---|---|---|
| ID | int | 唯一識別碼（`$EventDone_{ID}` 引用） |
| Timing | string | 觸發時機（見上方「觸發時機」） |
| Condition | string | 觸發條件 |
| Priority | int | 同時機多事件命中時的執行順序（大→小） |
| OneTime | int | 1=一生只觸發一次 |
| DialogueID | int | 觸發的劇情對話（DialogueData 表），0=無 |
| PrePerformance | string | 對話前播放的演出 ID，空白=無 |
| PostPerformance | string | 指令結束後播放的演出 ID，空白=無 |
| Commands | string | 對話結束後執行的效果指令串 |
| Note | string | 備註 |

執行順序：`PrePerformance → 對話 → Commands → PostPerformance`。
同一時機的事件依 Priority 由大到小依序執行，**每個事件執行前都會重新檢查條件**
（前面的事件可能改變數值）。

> ⚠️ 互斥條件事件（如交易次數 1/2/3+）請把「較晚期」的條件設較高 Priority，
> 避免前一個事件把數值改到符合下一個事件的條件而連續觸發。
> 參考範例資料中 AfterAction:301 的 170/171/172。

## 6. GameTextData（遊戲文字表）

| 欄位 | 型別 | 說明 |
|---|---|---|
| ID | int | 唯一識別碼（`ShowHint(ID)` 引用） |
| Group | string | 群組名（`Monologue(群組)` 隨機抽選用） |
| Condition | string | 抽選/顯示條件 |
| Text | string | 文字內容（可用 `\n` 換行） |
| Weight | int | 隨機抽選權重（預設 1） |
| Note | string | 備註 |

目前使用的群組：`MorningIdle`（早晨自言自語）、`SearchAgain`（重複搜索）、
`Hint`（提示視窗）、`Credits`（製作名單，ID 950，可在 GameLauncher Inspector 改）。

## 7. DialogueData（劇情對話表）— KahaGameCore Dialogue System 格式

| 欄位 | 型別 | 說明 |
|---|---|---|
| ID | int | 對話 ID（同一段劇情的所有行共用） |
| Line | int | 行號（從 1 開始，依序執行） |
| Command | string | 對話指令 |
| Arg1~Arg5 | string | 指令參數 |
| Arg1_en 等 | string | 多語系欄位（目前未使用，可留空） |

常用對話指令（完整清單見 DialogueSystem 內建指令）：

| Command | Arg1 | Arg2 | Arg3 | 說明 |
|---|---|---|---|---|
| `Say` | 說話者（空=旁白） | 內容 | | 顯示一句對話 |
| `AddOption` | 選項文字 | 目標對話ID | 目標行號 | 加入一個選項 |
| `ShowOptions` | | | | 顯示已加入的選項並等待選擇 |
| `GoToLine` | 行號 | | | 跳到本對話指定行 |
| `BlackIn` / `BlackOut` | 秒數 | | | 黑幕進/出 |
| `ShowFullScreenImage` | 圖片名 | 淡入秒數 | | 顯示全螢幕 CG（Addressables 鍵值） |
| `HideFullScreenImage` | 圖片名 | 淡出秒數 | | 隱藏全螢幕 CG |
| `ShowCharacter` 等 | | | | 立繪相關指令（位置 Left/Middle/Right） |
| `GameEffect` | 效果指令串 | | | **本專案擴充**：在對話中執行遊戲效果指令（如 `ShowHint(901)`） |

### CG 佔位規則

目前沒有圖片素材，劇情中以 `{顯示CG:名稱}` 寫在 Say 的內文中佔位。
素材到位後：
1. 將圖片加入 Addressables，鍵值=CG 名稱（沿用 KahaGameCore 的 `AddressablesCGProvider`）。
2. 把佔位的 Say 行改為 `ShowFullScreenImage(CG名稱)` / `HideFullScreenImage(CG名稱)`。

## 演出（Performance）串接說明

表格中所有 `PrePerformance` / `PostPerformance` / `PlayPerformance(ID)` 引用的演出 ID，
都對應一個 `IStagePerformance` 實作：

```csharp
public class HusbandLeavePerformance : IStagePerformance
{
    public async UniTask PlayAsync() { /* UGUI 動畫 */ }
}
```

在 `GameLauncher.RegisterPerformances()` 註冊：
`services.PerformancePlayer.Register("HusbandLeave", new HusbandLeavePerformance(...));`

**未註冊的演出 ID 不會卡流程**，會輸出 `[演出預留] ID` 的 Log 並以 0.5 秒停頓代替。
目前表格已使用的演出 ID 一覽（皆為預留，待實裝）：

| 演出 ID | 場景 |
|---|---|
| `Opening` | 開場 |
| `DayChange` | 換日 |
| `HusbandLeave` / `HusbandReturn` | 丈夫外出 / 返家 |
| `UnlockOuting` | 外出選項開放 |
| `UnlockMap` | 新地點開放 |
| `Cleaning` / `CookMeal` / `Rest` / `Sleep` | 行動演出 |
| `Dinner` | 晚餐料理 |
| `SupplyGain` | 物資增加 |
| `SweetDay` | 甜蜜的一天 |
| `TimeSkip` | 最終事件前的時間推進 |
| `Credits` | 製作人員名單（已用 CreditsView 實作，為串接範例） |

## 場景與 Prefab 建置

選單 **ProjectII → Build UI Prefabs And Scene** 會自動產生：
- `Assets/ProjectII/Resources/UIViews/` 下的所有 View prefabs
- `Assets/Scenes/Game.unity`（含 MainCanvas、UserInterfaceController、DialogueView、GameLauncher）

版面以 **3840x2160（4K）** 為設計解析度（CanvasScaler 參考值，其他解析度等比縮放）。
KahaGameCore 的 DialogueView prefab 為 1080p 設計，場景中以 `DialogueScaleRoot`
（1920x1080、scale 2）包覆放大，美術請勿直接改動該容器的尺寸與縮放。

> 注意：重跑會覆寫 prefabs 與場景，美術調整後請勿重跑，或先備份。

## 其他注意事項

- **中文字型**：TMP 預設字型不含 CJK 字元，請建立中文 TMP Font Asset 並設為預設
  （Window → TextMeshPro → Font Asset Creator），否則中文會顯示為方塊。
- 表格數值（打掃/進食的增減量等）皆為暫定值，直接在 Google Sheet 調整即可。
- 劇情文本中標示「（…文本預留…）」的行請於 DialogueData 表填寫實際內容。
